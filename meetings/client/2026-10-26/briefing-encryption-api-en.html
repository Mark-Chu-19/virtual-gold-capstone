Virtual Gold / Privacy serviceAPI briefing · Conversation Key Manager

Redact. Restore. Close the conversation.

One API, two encryption modes. Each conversation has an independent random key. Restoration resolves tokens directly from the message.

Two modes. Choose whether to retain mappings.

Both modes are implemented. Select with tokenization.mode; the default is mapping.

Independent conversation keys · Implemented
mapping · Default

Reference token + encrypted mapping

The token references a server-side mapping. Original values are encrypted before storage.

  • Stored values use AES-SIV with a conversation-derived key.
  • Delete mappings to invalidate that group’s Mapping tokens.
  • Requires persistent mappings and conversation key records.
aes_siv · Alternative

Replace with authenticated ciphertext

Original values are encrypted into tokens. No original-value mapping is stored.

  • Fixed conversation keys and AAD keep tokens stable for the same value and type.
  • Restoration needs the key record. Closing the conversation blocks new-format tokens.
  • Length grows with UTF-8 input size. Models must preserve the token exactly.
Key protectionEach conversation gets random key material, wrapped by a master KEK. HKDF derives separate keys by purpose. Replicas share Redis; clients never receive keys.
RecommendationChoose Mapping when mappings are acceptable and need separate cleanup. Choose AES-SIV to avoid original-value mappings. Both use long tokens with conversation locators and require key storage.

Tokens such as [VG:2:…], req_… and placeholder values are illustrative, not decryptable. Use full tokens from actual responses. This page makes no service requests.

The client supplies the conversation ID. The service manages keys.

group_id is the client’s existing business conversation ID. Reuse it for initial and subsequent redactions. The service does not issue a new business conversation ID in the response.

01 / REDACT

Original text + group_id + mode

The first request creates an independent random key and internal handle. Later requests reuse them. Valid existing tokens are preserved; only new private content is replaced.

02 / AGENT

Pass the complete redacted message

Tokens carry the internal handle, not the original group_id. Agents pass them unchanged, without managing keys or redaction IDs.

03 / RESTORE

text + authentication

Tokens locate the conversation key. The service checks permissions and expiry, then restores. No separate group_id or mode is needed.

04 / DELETE

Reuse the original group_id

Put the business conversation ID in the URL. Delete mappings or close the whole conversation. DELETE does not locate conversations from tokens.

Clients maintain the business conversation association: send group_id in redaction bodies and reuse it in DELETE URLs. Omitting it uses default, sharing one conversation within the tenant.

Runnable example: redact → restore → close

# Prerequisites: VG_TOKEN_KEYS configured on the server; an authorized API key; jq installed.
BASE=http://127.0.0.1:8080
GROUP=conversation_001   # Client business conversation ID, authorized within the tenant
MODE=aes_siv             # Change to mapping if needed; restoration stays the same
: "${VG_API_KEY:?Set the client API key first}"

REQUEST=$(jq -n --arg group "$GROUP" --arg mode "$MODE" \
  '{purpose:"Draft a reply",email:{body:"Call 202-555-0102"},group_id:$group,tokenization:{mode:$mode}}')
REDACTED=$(curl --fail-with-body -sS "$BASE/v2/redactions" \
  -H "Authorization: Bearer $VG_API_KEY" \
  -H 'Content-Type: application/json' -d "$REQUEST")

# Normally pass this to an agent; here, send redacted text back to test the round trip.
printf '%s' "$REDACTED" | jq '{text:.redacted_email.body}' | \
  curl --fail-with-body -sS "$BASE/v2/restorations" \
    -H "Authorization: Bearer $VG_API_KEY" \
    -H 'Content-Type: application/json' --data-binary @-
# Returns RESTORED with restored_text: "Call 202-555-0102".

# Close when the conversation ends, using the GROUP retained by the client.
curl --fail-with-body -sS -X DELETE "$BASE/v2/groups/$GROUP" \
  -H "Authorization: Bearer $VG_API_KEY"
# Returns 204. Format-2 tokens can no longer restore; new redactions for this group return 410.
# To delete mappings only, use /v2/groups/$GROUP/mappings.
Lifetimettl_seconds extends the conversation idle deadline without shortening it, subject to a fixed maximum lifetime (24 hours by default). expires_at is a deadline snapshot. Use a new business group ID after expiry or closure.
Idempotent retriesOptional Idempotency-Key: the same tenant, key and input reuse the result. Conflicts or in-progress duplicates return 409. Replays check conversation state and cannot bypass closure.
Request contextOnly content explicitly supplied in the request is analyzed. Pass historical content in email.thread; group_id does not load conversation history.

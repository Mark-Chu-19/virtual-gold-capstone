Virtual Gold / Privacy serviceAPI briefing · Conversation Key Manager

脱敏、恢复、会话清理。

一套 API，两种加密模式。每个 conversation 使用独立随机密钥，恢复直接解析消息中的 token。

双模式选型：是否保留原文映射。

两种模式均已实现，通过 tokenization.mode 选择，默认 mapping。

会话独立密钥 · 已实现
mapping · 默认

引用 token + 加密映射

token 定位服务端映射；原文加密后保存在后台。

  • 后台使用会话派生密钥和 AES-SIV。
  • 可删除映射，使该组 Mapping token 失效。
  • 需要持久化 mapping 和会话密钥记录。
aes_siv · 可选

认证密文直接替换

原文直接加密成 token，不保存原文 mapping。

  • 固定会话密钥与 AAD，同值、同类型的 token 稳定。
  • 恢复需会话密钥记录；关闭会话可阻断新格式 token。
  • 长度随 UTF-8 原文增长，模型需原样传递。
密钥保护每个 conversation 随机生成密钥材料；主密钥 KEK 封装保存，HKDF 按用途派生。多实例共享 Redis；客户端不接触密钥。
选型建议允许保存映射、需要独立清理映射时选 Mapping；不保存原文映射时选 AES-SIV。两者都使用带会话定位信息的长 token，都依赖会话密钥存储。

会话 ID 由业务系统提供，密钥由服务端管理。

group_id 就是客户端已有的 conversation ID。首次及后续脱敏使用同一个 ID；服务不会在响应中分发新的业务 conversation ID。

01 / REDACT

原文 + group_id + mode

首次创建独立随机密钥与内部 handle，后续复用。已有合法 token 保留，只处理新增隐私。

02 / AGENT

传递完整脱敏消息

token 带内部会话 handle，不带原始 group_id。跨 agent 原样传递，不保存密钥或 redaction ID。

03 / RESTORE

text + 鉴权

从 token 自动定位会话密钥，校验权限、期限并恢复。无需另传 group_id 或 mode。

04 / DELETE

使用原来的 group_id

路径中提交业务会话 ID。可只删 Mapping，或关闭整个会话；DELETE 不通过 token 定位。

客户端需要维护业务会话关联：脱敏时在请求体传 group_id，删除时在 URL 传同一个 ID。省略时使用 default，同一 tenant 下这些请求会共享一个会话。

可执行示例：脱敏 → 恢复 → 关闭

# 前提：服务已配置 VG_TOKEN_KEYS；API key 已获授权；已安装 jq。
BASE=http://127.0.0.1:8080
GROUP=conversation_001   # 客户端业务会话 ID，需在该 tenant 的授权范围内
MODE=aes_siv             # 可改为 mapping；恢复调用不变
: "${VG_API_KEY:?请先设置客户端 API key}"

REQUEST=$(jq -n --arg group "$GROUP" --arg mode "$MODE" \
  '{purpose:"Draft a reply",email:{body:"Call 202-555-0102"},group_id:$group,tokenization:{mode:$mode}}')
REDACTED=$(curl --fail-with-body -sS "$BASE/v2/redactions" \
  -H "Authorization: Bearer $VG_API_KEY" \
  -H 'Content-Type: application/json' -d "$REQUEST")

# 实际接入时先交给 agent；此处回传脱敏文本，验证 round trip。
printf '%s' "$REDACTED" | jq '{text:.redacted_email.body}' | \
  curl --fail-with-body -sS "$BASE/v2/restorations" \
    -H "Authorization: Bearer $VG_API_KEY" \
    -H 'Content-Type: application/json' --data-binary @-
# 返回 RESTORED，restored_text 为 "Call 202-555-0102"。

# 会话结束后关闭；仍用客户端保存的 GROUP。
curl --fail-with-body -sS -X DELETE "$BASE/v2/groups/$GROUP" \
  -H "Authorization: Bearer $VG_API_KEY"
# 返回 204；格式 2 token 随后无法恢复，该 group 的新脱敏返回 410。
# 仅清理 Mapping 则调用 /v2/groups/$GROUP/mappings。
有效期ttl_seconds 延长会话空闲期限，不缩短已有期限；受固定最大寿命限制，默认 24 小时。响应的 expires_at 是会话期限快照。过期或关闭后使用新的业务 group ID。
幂等重试可选 Idempotency-Key。同 tenant、同 key、同输入复用结果；冲突或处理中返回 409。缓存重放也检查会话状态；关闭会话后不能通过缓存绕过。
运行条件跨实例使用持久化 Redis，共享 keyring 与身份配置。AES-SIV 不保存原文映射，但也需要会话密钥存储。真实模型对长 token 的保留效果需单独评估。
